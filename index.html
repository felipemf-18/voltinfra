Data Sovereignty

Zero Data Retention (ZDR) Commitment

VoltInfra operates strict stateless pass-through inference. Prompts, completions, and token payloads are processed exclusively in volatile memory and instantly evicted post-stream. No input or output data is logged to non-volatile storage, cached, or used for model training under any circumstances.

100% Volatile Execution

KV cache tensors and model activations reside solely in volatile memory and are purged immediately upon connection termination.

Zero Non-Volatile Logs

Prompt logging is disabled in the serving runtime. No customer query payloads are written to SSDs, disks, databases, or object storage.

Zero Model Re-Training

User inputs and completions are never aggregated, pooled, or utilized for model fine-tuning, training datasets, or evaluation.

Frequently Asked Questions

Questions & Answers

Is VoltInfra drop-in compatible with the official OpenAI SDKs? +

Yes. Point base_url to https://api.voltinfra.com/v1 and use model: "qwen/qwen3-8b". All standard parameters such as stream, temperature, max_tokens, and tool use formats work out of the box.

How is Zero Data Retention enforced technically? +

Our containerized inference runtimes run without persistent volume mounts for logs. Payload logging flags are permanently disabled, and the reverse proxy routes requests via memory streams directly to the CUDA engine.

What latency and throughput can we expect on production workloads? +

For typical conversational prompts (500–1000 input tokens), median Time To First Token (TTFT) is ~380–420 ms. Sustained generation throughput ranges from ~55 to 65 tokens per second with AWQ INT4 Marlin kernels.

How do compute aggregators (like OpenRouter) audit our endpoints? +

Aggregators can run standard synthetic benchmark suites directly against our endpoints. We provide dedicated sandbox keys and audit telemetry upon request via ops@voltinfra.com.
